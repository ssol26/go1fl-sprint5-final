## Что реализовано

### `personaldata`

- Экспортируемая структура `Personal` с полями `Name`, `Weight`, `Height`.
- Метод `Print()` выводит данные в формате:

```text
Имя: <Имя_пользователя>
Вес: <Вес_пользователя>
Рост: <Рост_пользователя>
```

Числовые значения выводятся с двумя знаками после запятой, как требуют тесты.

### `spentenergy`

- `Distance()` — расчёт дистанции в километрах через длину шага и коэффициент `stepLengthCoefficient`.
- `MeanSpeed()` — средняя скорость; при неположительных шагах или длительности возвращает `0`.
- `RunningSpentCalories()` — калории при беге, с проверкой входных параметров.
- `WalkingSpentCalories()` — калории при ходьбе, с корректирующим коэффициентом `walkingCaloriesCoefficient`.
- Для калорий проверяется, что шаги, вес, рост и длительность больше нуля. При некорректных значениях возвращаются `0` и ошибка.

### `trainings`

- Структура `Training` с полями `Steps`, `TrainingType`, `Duration` и встроенной `personaldata.Personal`.
- `Parse()`:
  - проверяет, что строка содержит ровно 3 поля;
  - преобразует шаги через `strconv.Atoi`;
  - проверяет, что шаги больше нуля;
  - преобразует длительность через `time.ParseDuration`;
  - проверяет, что длительность больше нуля;
  - записывает данные только после успешной валидации.
- `ActionInfo()`:
  - считает дистанцию и среднюю скорость;
  - выбирает расчёт калорий для `Бег` или `Ходьба`;
  - возвращает ошибку `неизвестный тип тренировки` для остальных значений;
  - формирует строку в формате из технического задания.

### `daysteps`

- Структура `DaySteps` с полями `Steps`, `Duration` и встроенной `personaldata.Personal`.
- `Parse()` разбирает строку из двух полей, проверяет шаги и длительность.
- `ActionInfo()` считает дистанцию и калории, при ошибке возвращает пустую строку и ошибку, иначе формирует строку в формате из технического задания.

### `actioninfo`

- Интерфейс `DataParser` с методами `Parse(string) error` и `ActionInfo() (string, error)`.
- `Info()` перебирает `dataset`, вызывает `Parse()` и `ActionInfo()`, логирует ошибки и пропускает проблемную запись, а успешный результат выводит через `fmt.Println`.

## Как отправить работу на ревью

В `result` уже есть ветка `first-iteration` с одним коммитом. Ветка `main` — это исходный шаблон; отправлять её в новый репозиторий не нужно.

1. Откройте шаблон `Yandex-Practicum/go1fl-sprint5-final`, нажмите `Use this template` → `Create a new repository` и создайте репозиторий на своём аккаунте. Не добавляйте README, `.gitignore` и лицензию: создавайте репозиторий без дополнительных файлов.

2. Склонируйте новый репозиторий в отдельную папку:

```bash
git clone https://github.com/<ваш-логин>/<имя-репозитория>.git tracker-review
cd tracker-review
```

3. Перенесите коммит из `result` в новую ветку поверх `main`:

```bash
git remote add solution "<абсолютный путь к папке result>"
git fetch solution first-iteration
git switch -c first-iteration
git cherry-pick solution/first-iteration
git remote remove solution
```

4. Проверьте, что тесты проходят:

```bash
go test -count=1 ./...
git log --oneline --decorate -3
git status --short
```

5. Отправьте ветку в новый репозиторий:

```bash
git push -u origin first-iteration
```

6. На GitHub нажмите `Compare & pull request`. Базовая ветка — `main`, сравниваемая — `first-iteration`. Название, например, `Первая итерация`. Создайте PR.

7. Дождитесь завершения GitHub Actions на вкладке `Actions`. Все проверки PR должны быть зелёными.

8. Скопируйте URL Pull Request вида `https://github.com/<ваш-логин>/<имя-репозитория>/pull/1` и отправьте его в Практикуме на вкладке «Ревью».

Важно:

- не отправляйте `main` и не делайте force push;
- не создавайте PR в репозитории `Yandex-Practicum/go1fl-sprint5-final`;
- отправляйте именно URL PR, а не URL репозитория;
- если репозиторий private, дайте ревьюеру доступ или сделайте его public;
- в PR не должно быть изменений в `*_test.go` и `cmd/tracker/main.go`.

Если cherry-pick не проходит из-за конфликта, используйте резервный вариант:

```bash
git cherry-pick --abort
rsync -a --exclude='.git' "<абсолютный путь к папке result>/" ./
git add .
git commit -m "Финальное задание модуля 1: Go"
git push -u origin first-iteration
```

## Если ревьюер попросит доработки

```bash
git add .
git commit -m "Исправления по замечаниям ревью"
git push
```

После push новый коммит появится в PR. Затем снова отправьте ссылку на PR через форму «Ревью» в Практикуме — как сказано в инструкции, без повторной отправки ссылки ревьюер не увидит изменения.
